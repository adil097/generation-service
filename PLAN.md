## Текущая точка

**Все 11 этапов завершены.** Сервис реализует все пять HTTP-методов,
проверку HMAC, атомарные финансовые операции, fallback, сторож и восстановление
сохранённой работы. Проверены обязательные сценарии задания и дополнительные
гонки и падения процессов. Матрица покрытия — [docs/testing.md](docs/testing.md).

README приведён к окончательному виду: быстрый запуск, настройки, seed,
миграции и создание следующей ревизии, полный набор тестов, HTTP-примеры,
финансовые гарантии и правило позднего результата. Уточнены ограничения
прямого запуска Python и отличие быстрых тестов от полного набора в Compose.
В отдельном Compose-проекте выполнена сборка без кеша и запуск с новым томом:
миграции до 0002, повторный seed, реальная генерация, подписанная оплата
с повторной доставкой и сохранность результата после пересоздания контейнеров.
Проверено создание пустой ревизии Alembic во временной копии migrations,
её применение и откат. Все 350 тестов проходят на PostgreSQL без пропусков.
`.env` исключён из Git и Docker-сборки; в Git хранится шаблон с локальными
значениями, проверка распространённых форматов секретов совпадений не дала.
Рабочий проект и его данные сохранены, проверочные контейнеры, сеть и том удалены.

Вне репозитория остались вспомогательные файлы в `%TEMP%`:
`task-job-check-20261024.env`, `task-job-check-20261024-state.json` и каталог
`task-job-check-20261024-migrations`. Автоматическая проверка инструмента
отклонила их удаление (`blocked by policy`); на запуск проекта они не влияют.

## Этапы реализации

- [x] **1. Создать каркас проекта.** Инициализировать Git, создать структуру
  каталогов, описание и фиксацию зависимостей, настройки, `.gitignore`
  и `.env.example`. Критерий завершения: зависимости устанавливаются,
  минимальное приложение импортируется, настройки читаются из окружения.

- [x] **2. Подготовить Docker Compose.** Добавить Dockerfile, PostgreSQL
  с постоянным томом, основной сервис в четыре воркера и два сервиса-заготовки
  провайдеров. Настроить проверки готовности. Критерий завершения:
  все компоненты запускаются через `docker compose up`.

- [x] **3. Создать схему БД через Alembic.** Реализовать таблицы, связи,
  ограничения, индексы и роли по архитектуре. Добавить каталог моделей и ног,
  воспроизводимое создание тестовых пользователей и начального журнала.
  Критерий завершения: миграции применяются к пустой БД, начальные данные
  соответствуют заданию.

- [x] **4. Реализовать финансовые операции.** Чтение баланса и журнала,
  начисление оплаты, списание и возврат. Соблюсти блокировки, атомарность
  и уникальность операций. Критерий завершения: повторные и конкурентные
  события не дублируют финансовый эффект, баланс не становится отрицательным.

- [x] **5. Реализовать создание задачи.** Проверить модель, референсы,
  баланс и лимит трёх активных задач. Одной транзакцией создать задачу,
  списание и первую попытку с сохранённым запросом провайдеру.
  Критерий завершения: отклонённый запрос не сохраняет задачу или списание;
  конкурентные запросы соблюдают баланс и лимит.

- [x] **6. Реализовать `finish_attempt`.** Объединить успех, отказ провайдера,
  ошибку отправки и таймаут. Реализовать выбор следующей ноги, окончательность
  закрытой попытки и единственный возврат. Критерий завершения:
  переходы соответствуют разделам 3–4 архитектуры и выполняются атомарно.

- [x] **7. Написать фейковых провайдеров.** Реализовать идемпотентный
  `POST /tasks`, сохранение состояния, генерацию результатов, подпись
  и повторную доставку вебхуков. Добавить все сценарии сбоев из задания.
  Критерий завершения: один ключ создаёт одну генерацию, состояние переживает
  рестарт, сценарии управляются настройками.

- [x] **8. Реализовать отправку и фоновые процессы.** Добавить захват попытки
  с токеном и сроком действия, HTTP-вызов, сохранение ответа, восстановление
  `pending` и сторож. Критерий завершения: четыре процесса не теряют работу;
  падение после приёма провайдером не создаёт повторную внешнюю задачу;
  устаревший исполнитель не меняет состояние, общий дедлайн не продлевается.

- [x] **9. Подключить все API-эндпоинты.** Генерация, вебхуки провайдеров
  и платежей, чтение задачи с историей, чтение баланса с журналом.
  Добавить проверку HMAC по сырому телу и согласованные ответы об ошибках.
  Критерий завершения: API работает по контракту задания и вызывает общие
  бизнес-операции без дублирования логики.

- [x] **10. Проверить конкурентность и падения.** Пройти четыре обязательных
  теста из задания и дополнительные сценарии из архитектуры: баланс, лимиты,
  модерация, `payload`, устаревшие события, токены отправки и восстановление.
  Критерий завершения: проверки проходят на настоящем PostgreSQL через
  независимые соединения, включая работу нескольких процессов.

- [x] **11. Написать README и проверить чистый запуск.** Описать настройки,
  запуск, применение и добавление миграций, запуск тестов, финансовые гарантии,
  поздние результаты и восстановление. Проверить весь путь с пустой БД.
  Критерий завершения: репозиторий воспроизводимо запускается по README,
  обязательные тесты проходят, секреты не попадают в Git.

## Как обновлять этот файл

- Перед началом работы читать план и соответствующий раздел архитектуры.
- Завершённый этап отмечать `[x]` только после выполнения его критерия.
  Частичный результат записывать под этапом, оставляя чекбокс открытым.
- Обновлять «Текущую точку» и дату при изменении прогресса.
- Тесты ключевых механизмов добавлять по мере реализации; этап 10 —
  проверка полноты и интеграции, а не начало написания всех тестов.
- Изменение принятого решения отражать и в архитектуре, и в этом плане.
- Каждый законченный логический этап фиксировать коммитом, объясняющим,
  почему выбран такой подход. Крупный этап может состоять из нескольких коммитов.
- В журнале ниже кратко указывать сделанное и фактически выполненные проверки.
